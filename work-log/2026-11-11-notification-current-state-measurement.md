# 실시간 알림 현황 측정 (고도화 전 근거)

- 작업일: 2026-11-11
- 관련: 고도화 항목 "실시간 알림" (알림 DB 저장·목록 API, Redis Streams·SSE, 다중 서버 전달, 재접속 복구, 순번 알림 묶음). 이슈 미생성
- 기반: `dev@a44952e`, 로컬 Mac, 전용 DB `catchtable_loadtest`, 앱 포트 8089, k6 v2.1.0 + `k6/x/sse` v0.2.0

## 배경과 목표

현재 SSE 알림은 서버 메모리의 emitter 목록에 바로 쓰고 어디에도 남기지 않는다. 팀이 예상한 문제(미접속 시 유실, 기록 없음, 재연결 공백, 전송 동기 실행, 순번 알림 폭주)가 실제로 있는지 숫자로 확인해 고도화 근거로 쓴다. 앱 코드는 바꾸지 않았다. 스크립트는 [scripts/notification-loadtest](../scripts/notification-loadtest/README.md).

## 판단과 근거

- 부하 한계가 아니라 "알림이 빠지는가"를 재는 것이 목적이라, 실험마다 **발생 건수 vs 수신 건수**를 센다. 이 지표는 로컬이든 배포든 같다.
- 서버 30분 타임아웃·EventSource 3초 재연결은 클라이언트가 5초 연결·3초 끊김을 반복하는 것으로 줄여 재현했다(서버 수정 없음).
- 대기열 변경 이벤트는 점주 `/call`로 일으킨다. 호출 1회 = 호출 당사자에게 `WAITING_CALLED` 1건 + ACTIVE 전원에게 `WAITING_POSITION_CHANGED` 1건씩이므로 기대 수신 = 호출 수 × N.
- 호출된 웨이팅은 `CALLED`가 되어도 ACTIVE로 남는다. 그래서 호출은 누구의 순번도 바꾸지 않는다. 이 실험들에서 나간 순번 알림은 전부 직전과 같은 순번을 다시 보낸 것이다. 순번이 실제로 바뀌는 것은 입장·취소·노쇼·만료처럼 대기열에서 빠질 때다.
- 응답 시간은 클라이언트와 서버가 같은 머신이라 절대값이 아니라 N에 따른 추세만 근거로 쓴다. 호출은 웨이팅 1건당 1번만 되어 N=10에 맞춰 10회씩만 쟀다. 표본이 적어 p95는 참고값이고 p99는 내지 않았다.

실험 6의 개선 기대치(계산값, 미측정): 순번이 바뀐 사람에게만 보내면 이 조건에서 0건, 매장별로 1초 모아 보내면 약 2,000건(10초 × 200명).

### 원인 (코드 확인)

- `WaitingQueueNotifier`가 `WaitingQueueChangedEvent`마다 매장의 ACTIVE 웨이팅 전체를 조회해 한 명씩 보낸다. 이전 순번과 비교하지 않는다.
- `NotificationService.send()`가 수신자마다 `NotificationSettingService.allows()`를 부른다. `WAITING_POSITION_CHANGED`는 선택 알림이라 설정 테이블을 사람마다 조회한다. 500명이면 호출 1번에 조회 500번이다.
- `@Async` 설정이 없어 위 조회와 전송이 모두 점주 `/call` 요청 스레드에서 끝난 뒤에 응답한다. 실험 5의 지연은 이 세 가지가 합쳐진 결과다.

부수 관찰: 클라이언트가 SSE를 끊을 때마다 서버 로그에 `IOException: Broken pipe` 스택트레이스가 ERROR로 남는다(첫 전체 실행에서 2,858건). 정상 종료를 오류로 기록하는 셈이라 고도화 때 같이 정리할 만하다.

2026-11-11 정정: 처음에는 실험 6을 "1인당 50건 중 의미 있는 값 1건"으로 적었다. 호출이 순번을 바꾸지 않는다는 점을 놓친 서술이라 "실제로 바뀐 알림 0건"으로 고쳤다. 수치(10,000건, 1인당 50건)는 그대로다.

## 남은 점과 후속 작업

- 실험 4(서버 재시작 중 유실)는 절차만 README에 적고 실행하지 않았다.
- nginx 유휴 타임아웃(하트비트 없음)과 slow consumer는 로컬 구성이 더 필요해 범위에서 뺐다.
- 실험 6은 호출만 썼다. 입장·취소처럼 순번이 실제로 바뀌는 경우의 전송량은 재지 않았다.
- 실험 5의 표본을 늘리려면 웨이팅을 N보다 많이 만들고 그중 N명만 SSE로 연결해 호출 횟수를 늘리면 된다.
- 고도화 구현 후 같은 스크립트로 after 수치를 채운다.
