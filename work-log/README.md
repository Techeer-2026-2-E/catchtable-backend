# 작업 기록

변경의 이유와 확인한 결과를 남긴다. 현재 구성은 [PROJECT.md](../docs/PROJECT.md), 요구사항·정책·설계는 그 문서가 연결하는 Notion, 진행 상태는 GitHub 이슈·PR에서 확인한다.

## 언제 남기나

- API·SSE 이벤트 계약, 예약·웨이팅 상태 흐름, 데이터·마이그레이션, 동시성 처리에 중요한 변경이 있을 때.
- 대안과 선택 이유를 다음 작업자에게 전달해야 하거나, 중요한 장애·회귀를 수정했을 때.
- 이미 Notion ERD에 판단 근거가 있으면 링크하고 실제 변경·검증만 보충한다. 오탈자·서식·작은 동작 보존 수정은 PR 본문의 문제·변경·검증으로 충분하다.

## 작성 방법

[양식](../docs/templates/work-log.md)을 복사해 `{이슈번호}-{영문-slug}.md`로 만든다. 이슈가 없으면 `{YYYY-MM-DD}-{slug}.md`를 사용한다. 같은 작업의 후속 결과는 같은 파일에 날짜·PR별로 덧붙일 수 있다.

배경·범위, 실제 판단과 근거, 변경, 검증, 남은 점을 담는다. 8개 절을 기계적으로 채우거나 검토하지 않은 대안을 만들 필요는 없다. 빈 양식을 실제 기록처럼 추가하지 않는다. 토큰·실제 개인정보·원문 대화 전체는 넣지 않는다.

PR에서 해당 기록을 연결한다. 별도 수동 인덱스나 PR 상태표는 관리하지 않는다. 기록의 옛 판단을 덮어쓰지 말고 사후 정정은 날짜를 붙인다. 현재 설명이 바뀌면 관련 현재 문서도 갱신한다.

## 찾는 방법

이 폴더에서 이슈 번호·도메인·API·상태명으로 검색한다. 파일 목록과 PR 링크로 찾으므로 기록 추가 때 이 README를 수정할 필요는 없다.

[문서 운영 구성 기록](2026-10-27-ai-workflow.md)부터 적용했다. 그 이전의 [개발 의사결정 기록](https://github.com/Techeer-2026-2-E/catchtable-backend/blob/e6c668bbb6be920cb2ff47042e82edfe832c0a18/docs/development-decisions.md)은 원본을 보존하며 관련 작업에서 연결한다.

## 선택 CI

[비활성 워크플로 예제](../docs/templates/work-log-check.yml.example)는 `needs-work-log` 라벨이 있는 PR만 기록 파일 변경을 검사한다. 현재는 활성화하지 않았다. 파일 존재 검사는 내용의 품질 검토를 대신하지 않는다.
